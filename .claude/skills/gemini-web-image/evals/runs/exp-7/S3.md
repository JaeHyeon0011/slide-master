# Execution plan — Aside CLI not found (S3)

## Scenario (given)

The user asks to fill the `image_prompts.json` manifest through the
`gemini-web-image` skill. Running `aside --version` fails with "command not
found," and there is no Aside CLI at the default install locations either.
Proceed.

## Authority

Only `SKILL.md` and `scripts/gemini_web_image.py` are consulted. No outside
knowledge, no other file.

## Step-by-step plan

1. **Check the stated precondition** (`SKILL.md` §2, table row "Aside CLI
   installed"):

   ```bash
   aside --version
   ```

   Given result: fails, `command not found`.

2. **Decision point — before treating the CLI as absent, check every
   location the script itself checks**, because `SKILL.md` §2's own note on
   this row is just `aside --version`, but the script's `find_aside()` looks
   further than a bare `PATH` lookup (a fresh shell, or an agent's
   non-login shell, may not see a just-installed PATH entry yet). In the
   order `find_aside()` tries them:

   - `shutil.which("aside")` — i.e. is `aside` resolvable on `PATH` at all
     (already covered by step 1's failure, but this is the same check the
     script makes first)
   - `~/.local/bin/aside` (macOS/Linux)
   - `%LOCALAPPDATA%\Aside\CLI\current\aside.exe` (Windows — the junction
     `install.ps1` points at the newest release)
   - `%LOCALAPPDATA%\Aside\CLI\versions\*\aside.exe` (Windows — every
     installed version, newest first)

   ```bash
   ls -la ~/.local/bin/aside 2>/dev/null
   ```

   (On Windows: check `%LOCALAPPDATA%\Aside\CLI\current\aside.exe` and
   `%LOCALAPPDATA%\Aside\CLI\versions\` for any `aside.exe`.)

   Given result (per scenario: "no Aside CLI at the default install
   locations"): none of these exist either — the same outcome
   `find_aside()` would reach, returning `""`.

3. **Decision point — precondition confirmed failed.** Two sources agree on
   the branch to take:

   - `SKILL.md` §2, directly under the precondition table:

     > Stop and name the failed precondition. Do not fall back to another
     > image path from inside this skill — that decision belongs to the
     > caller.

   - The script's own `main()`, when `find_aside()` returns `""`:

     ```python
     if not aside:
         log("Aside CLI not found. Install it (macOS/Linux: `curl -fsSL "
             "https://releases.aside.com/install.sh | bash`; Windows: `irm "
             "https://releases.aside.com/install.ps1 | iex`), open the Aside app, "
             "sign in to Gemini there, then rerun. The manifest is untouched.")
         sys.exit(1)
     ```

   Branch taken: **stop here.**
   - Do not run `scripts/gemini_web_image.py --manifest ...` — it would only
     print the same failure and exit `1` without touching the manifest, so
     running it adds nothing.
   - Do not reach for another image-generation path on my own initiative
     (not `image_gen.py`'s CLI/API backend, not codex, not Kimi/WebBridge).
     Choosing a fallback path belongs to the caller (e.g. ppt-master's Step
     6), not to this skill.

4. **Do not run the installer myself.** `curl -fsSL
   https://releases.aside.com/install.sh | bash` (macOS/Linux) or `irm
   https://releases.aside.com/install.ps1 | iex` (Windows) downloads and
   executes a remote script. That is the user's call to make and run in
   their own shell, not something to pipe into a shell on their behalf.
   This plan names the exact command; it does not execute it.

5. **Report the failed precondition to the user**, giving the install
   commands verbatim from `SKILL.md` §2, and wait for their direction:

   > The Aside CLI isn't installed — `aside --version` failed with "command
   > not found," and it isn't at the default fallback locations either
   > (`~/.local/bin/aside`, or on Windows
   > `%LOCALAPPDATA%\Aside\CLI\current\aside.exe` /
   > `%LOCALAPPDATA%\Aside\CLI\versions\*\aside.exe`). I can't run the
   > `gemini-web-image` skill to fill the manifest until it's installed.
   >
   > To install it yourself:
   > - macOS/Linux: `curl -fsSL https://releases.aside.com/install.sh | bash`
   > - Windows x64 (PowerShell): `irm https://releases.aside.com/install.ps1 | iex`
   >
   > After installing, open the Aside app and sign in to Gemini inside it at
   > `gemini.google.com/images` (Aside has its own browser profile, so a
   > regular Chrome sign-in doesn't carry over).
   >
   > Let me know once that's done and I'll rerun the manifest fill — or tell
   > me if you'd rather use a different image path instead.

6. **Manifest state**: left untouched. No row's `status` or `last_error`
   changes, and no file is written, because nothing in `run_batch` (the only
   place that mutates the manifest) executes — `main()` exits at the
   `find_aside()` check, before the manifest is even read.
