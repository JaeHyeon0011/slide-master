# Execution plan — Aside CLI not found

## Scenario

User asks to fill the `image_prompts.json` manifest via `gemini-web-image`.
`aside --version` fails with "command not found", and the Aside CLI is not
present at the default install locations either.

## Step-by-step plan

1. **Check the Aside CLI precondition** (SKILL.md §2, row "Aside CLI
   installed"):

   ```bash
   aside --version
   ```

   Observed result (given by the scenario): fails, `command not found`.

2. **Decision point — before concluding the CLI is absent, check the same
   fallback locations the script itself checks** (`find_aside()` in
   `scripts/gemini_web_image.py`, since PATH may not be updated in a fresh
   shell):

   - macOS/Linux: `~/.local/bin/aside`
   - Windows: `%LOCALAPPDATA%\Aside\CLI\aside.exe` and
     `%LOCALAPPDATA%\Aside\CLI\bin\aside.exe`

   ```bash
   ls -la ~/.local/bin/aside 2>/dev/null
   ```

   Given result (per scenario): none of these paths exist either — the same
   conclusion `find_aside()` would reach, returning `""`.

3. **Decision point — precondition failed.** Per SKILL.md §2:

   > Stop and name the failed precondition. Do not fall back to another
   > image path from inside this skill — that decision belongs to the
   > caller.

   and per the script's own `main()` behavior when `find_aside()` returns
   empty: it logs the install instructions and exits with status `1` without
   touching the manifest.

   Branch taken: **stop here**. Do not run
   `scripts/gemini_web_image.py`. Do not attempt any other image-generation
   path (e.g. `image_gen.py` CLI/API backend) on my own initiative — that
   choice belongs to the user/caller, not to this skill.

4. **Do not execute the installer myself.** Installing software (piping a
   remote script into a shell, or an equivalent Windows installer command) is
   an action the user should run themselves, not something to execute
   silently on their behalf. This plan surfaces the exact command; it does
   not run it.

5. **Report to the user**, naming the failed precondition and giving the
   install commands verbatim from SKILL.md §2, then wait for direction:

   > The Aside CLI isn't installed (or at least not on PATH or at the
   > default install locations I checked: `~/.local/bin/aside`,
   > `%LOCALAPPDATA%\Aside\CLI\...`), so I can't run the `gemini-web-image`
   > skill to fill the manifest.
   >
   > To install it yourself:
   > - macOS/Linux: `curl -fsSL https://releases.aside.com/install.sh | bash`
   > - Windows x64 (PowerShell): `irm https://releases.aside.com/install.ps1 | iex`
   >
   > After installing, open the Aside app and make sure Gemini is signed in
   > at `gemini.google.com/images` inside it (Aside has its own browser
   > profile, so a regular Chrome sign-in won't carry over).
   >
   > Let me know once that's done and I'll rerun the manifest fill, or tell
   > me if you'd rather use a different image-generation path instead.

6. **Manifest state**: left untouched — no rows are marked `Failed`, no
   files are written, because the script itself never ran (it only writes
   `last_error`/`status` changes from inside `run_batch`, which requires a
   successful `aside repl` invocation that never happens here).

## Summary of branches

| Check | Result | Action |
|---|---|---|
| `aside --version` | fails (`command not found`) | proceed to location check |
| Default install locations (`~/.local/bin/aside`, `%LOCALAPPDATA%\Aside\CLI\...`) | not found | precondition confirmed failed |
| Precondition failed | — | stop; do not run the script; do not silently switch to another image path; do not auto-install |
| — | — | report the failed precondition + install commands to the user; wait for them to install and confirm, or choose another path |
